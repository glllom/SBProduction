## [BACKLOG] Обязательные параметры/кастомизаторы для моделей дверей

**Контекст:** Требовать от менеджера ввод специфичных данных (например, тип стекла, нестандартный отступ) только для
конкретных моделей/семейств дверей при создании группы или валидации.

**Решение:**

1. **Кастомизаторы (`Customizer`):**
    - Флаг `is_required = models.BooleanField(default=False)`.
    - Флаги/список обязательных параметров: `par1_required`, `par2_required` (дефолтное значение параметра оставляется
      пустым).
2. **Привязка к модели:**
    - Связать обязательные кастомизаторы с `Product` через `effective_bom` или поле `required_customizers`.
    - При добавлении группы (`group-add`) они автоматически подгружаются в `group.customizers` с пустыми значениями.
3. **Валидация (`order-check-validation`):**
    - Проверять наличие обязательных кастомизаторов в группе и непустоту требуемых полей `par1...par5`.
    - Блокировать перевод заказа в производство при незаполненных параметрах.

## [BACKLOG] Архитектура панели действий производства и мастер-печати отчётов

**Контекст:** Панель действий заказа перегружена разрозненными кнопками участков производства. При запуске заказа или
фазы требуется выполнять полный комплекс действий (документы, ЧПУ-файлы, этикетки), сохраняя возможность выборочной
повторной печати или выгрузки конкретного участка.

**Решение:**

1. **Интерфейс панели действий (`order_detail.html`):**
    - **Главные действия процесса (Primary CTA):** Кнопки текущего статуса (`העבר לייצור`, `סיום שלב א`, `העברה לשלב ב`,
      `סיום ייצור`) запускают основной пайплайн.
    - **Панель инструментов (Bootstrap Collapse / Dropdowns):** Скрываемый блок «פעולות ייצור ומסמכים», разбитый на 3
      категории:
        - *דוחות ייצור:* Мастер-печать всех отчётов заказа + точечные ссылки на каждый задействованный участок.
        - *קבצי מכונות (CNC):* Скачивание общего архива (ZIP) + индивидуальные файлы станочных программ.
        - *מדבקות:* Печать всех термоэтикеток заказа + печать по типам изделий (коробки / полотна).
    - **Dev Tools:** Скрытое служебное меню (`Rebuild Spec`, snapshot diffs) только для админа/режима отладки.

2. **Мастер-печать отчётов (Print Aggregator):**
    - Единый эндпоинт отчётов `station-report/` с параметром `?station=ALL` собирает данные всех участков цепочки заказа
      в общий контекст `sections = [section1_data, section2_data, ...]`.
    - Главный шаблон `master_report.html` подключает изолированные модули участков (`includes/report_<station>.html`) в
      цикле.
    - Разделение листов через CSS (`page-break-before: always; break-before: page;`) гарантирует печать каждого участка
      с чистого листа при отправке задания на принтер в один клик.

## [BACKLOG] Механизм доделок и сервисных дозаказов (העבר לייצור השלמות)

**Контекст:**
После завершения Фазы 2 (`PHASE2_READY` / установка дверей) регулярно возникают задачи вторичного производства без
создания нового заказа:

- Разморозка стеновых панелей (`חיפוי`), точные замеры которых сняты после навески дверей.
- Дозаказ погонажа, наличников или сервисных реек по требованию монтажника с объекта.
- Экспресс-дозаказ стандартных дверей клиентом в завершённый интерьер.

**Архитектурное решение:**

1. **Жизненный цикл групп позиций (`OrderItemsGroup`):**
    - Поле статуса готовности группы: `production_state` (`WAITING`, `IN_PRODUCTION`, `COMPLETED`).
    - Группы со статусом `COMPLETED` блокируются от повторной генерации ЧПУ и исключаются из новых цеховых отчётов.

2. **Процесс «העבר לייצור השלמות»:**
    - Доступен из статуса `PHASE2_READY` или `READY`, если в заказе появились новые группы или были разморожены
      отложенные (`WAITING`).
    - Переводит заказ в активный статус производства доделок (`IN_PRODUCTION` / `COMPLETION_PRODUCTION`).
    - Запускает пайплайн спецификации и валидацию **только для незавершённых групп**.

3. **Спецификации и снимки (Snapshots):**
    - Единая спецификация Фазы 2 дополняется новыми позициями.
    - Фиксируется специализированный снимок дополнений (`snapshot_type='PHASE2_COMPLETION'`).
    - В цеховые отчёты и на станки уходят только дельта-позиции из текущей партии доделки.
